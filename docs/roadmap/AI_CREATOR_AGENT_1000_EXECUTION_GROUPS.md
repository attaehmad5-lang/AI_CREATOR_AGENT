## Execution orders — mandatory for every group

1. **Inspect before editing:** read relevant source, tests, configuration, roadmap IDs, git history, and current CI. Never assume a feature works because its file exists.
2. **Trace requirements:** map the group to existing canonical feature/task IDs. Record uncertainty; never silently rename, merge, or renumber canonical tasks.
3. **Design first:** state behavior, interfaces, data/security invariants, failure modes, dependencies, and measurable acceptance criteria before coding.
4. **Implement production-quality code:** no placeholder returns, fake integrations, swallowed exceptions, hard-coded secrets, unbounded network calls, or success without verified work.
5. **Test adversarially:** add/update unit, integration, negative, regression, concurrency, and fault-injection tests as applicable. Mock external services for deterministic tests; run live tests only against explicitly configured, authorized accounts/endpoints.
6. **Build → Test → Verify → PASS:** run targeted tests, relevant full suite, compile/lint/type/security checks available in the repository, and supported-platform CI. Diagnose and fix failures, then rerun; do not ignore or merely rerun failures.
7. **Inspect the diff:** ensure no credentials, tokens, private user data, generated junk, unrelated changes, or weakened checks are committed. Preserve secret-file ignore protections.
8. **Evidence before status:** record commit SHA, exact commands, platform, test counts/results, CI links, artifacts, and remaining gaps. Status values: VERIFIED, PARTIAL, OPEN, BLOCKED. File existence or unrelated green tests do not prove completion.
9. **Backup and review:** commit tested work to the intended working branch and confirm it exists on GitHub. Keep changes reviewable. Do not merge PRs or alter protected/default branches without explicit user approval.
10. **Dependencies and blockers:** work in dependency order; parallelize only independent groups. For credentials, billing, devices, or provider access, build safe test doubles and seams, then record live verification as BLOCKED until authorized access exists.
11. **Security and cost safeguards:** no paid generation, destructive migration, production deployment, credential rotation, or account-changing operation without explicit authorization. Preserve charge/quota reconciliation when failures may have incurred costs.
12. **No silent completion:** close a group only after code (if applicable), tests, evidence, docs, and ledger updates are complete. Otherwise leave it open with a reproducible blocker and next action.

## Definition of done for each group

- Acceptance criteria are satisfied.
- Implementation is integrated into the real call path, not just an orphan file or mock-only feature.
- Relevant positive, negative, edge, regression, and security tests pass.
- Relevant full-suite and CI checks pass, or an external/platform blocker is documented and status remains PARTIAL/BLOCKED.
- Failure behavior, timeouts, cleanup, privacy, and concurrency are addressed where applicable.
- Documentation and configuration examples match actual behavior.
- Evidence links and commit SHA are recorded in the canonical ledger.
- No unapproved merge and no unsupported 100% completion claim.
